# lecture-outline-design

> 把讲稿变成 eink-deck 可渲染的大纲 Markdown：一套「从讲稿到分镜」的教学设计方法论——核心思想、记忆钉、九步流程、三道交付闸门。

## 这是什么

`lecture-outline-design` 是一套**纯方法论技能**：它不渲染、不写 HTML、不定义语法，只回答"这一页，学生看到什么、听到什么、记住什么"，产出一份结构化的**大纲 Markdown**，交给下游 [eink-deck](https://github.com/Mercury-vivis/eink-deck) 渲染成可放映的 HTML PPT。

它解决的是 PPT 制作的**上游问题**——把线性听觉流（讲稿）转译为空间视觉块（分镜），让你"写大纲＝出成片"：

```
讲稿 .md ──▶ lecture-outline-design（九步方法论）──▶ 大纲 .md ──▶ eink-deck 渲染 ──▶ 翻页 HTML
```

## 核心主张

- **大纲不是讲稿的压缩版，是导演脚本**：判据只有一句——"这一句，学生是听更好，还是看更好？"听更好就不上屏。
- **核心思想＝框架的生成器**：幕 = 核心思想的论证推进步骤，不是话题并置。
- **写大纲即出图、即配真实图**：概念示意直接写成成品 SVG 语句，真实配图在大纲阶段下载+压缩一体完成，交付不带占位。

## 能力

- **准备步 + 九步**完整流程：定魂（核心思想）→ 立骨（记忆钉 / 切幕）→ 填肉（视听分工 / 选容器 / 标层级 / 写双栏）→ 校验（四道检验 + 三道闸）。
- **28 版式选型表**：信息关系 → 版式（L01–L27），含图表滥用红线、防空页规则、双基线垂直稳定机制。
- **课程档案方法论**：全系列共用约束的撰写六步、覆盖范围声明、活文档纪律。
- **三道交付闸门**：讲稿→大纲反向覆盖核对、页序单调校验、技能依赖扫描——防"整段漏落 / 时间倒序 / 联动失配"。

## 与 eink-deck 的关系（务必先读）

本技能**只写大纲、不写语法**。所有字段写法、版式挂载、渲染行为一律在 [eink-deck](https://github.com/Mercury-vivis/eink-deck) 一侧定义：

- 语法事实：`eink-deck/engine/generated/语法速查.md`（机器生成，勿手改）
- 可抄样例：`eink-deck/engine/generated/示例大纲.md`（28 版式逐式一页）
- 视觉规范：`eink-deck/templates/eink_模板模块规范.md`

> 本技能是 eink-deck 的**上游搭档**：你先在这里把讲稿变成大纲，再交给 eink-deck 出片。两者配合使用，构成一条"讲稿 → 大纲 → HTML"的轻量发布流。

## 安装

将本技能目录放入 WorkBuddy 的标准技能位置（与 [eink-deck](https://github.com/Mercury-vivis/eink-deck) 并排），并在对话中调用即可。无需任何本机绝对路径。

## 快速上手

1. 准备：授课讲稿（逐字稿或提纲稿）+ 硬约束（总时长 / 分块时长 / 互动次数）。
2. 走流程：准备步锁定输出契约 → 第 1 步提炼核心思想 → 第 2 步派生记忆钉 → … → 第 9 步四道检验 + 第 9.5 步三道闸。
3. 产出：一份 `课程文件夹/PPT制作/<讲次>·<标题>_大纲.md`，交给 eink-deck 渲染。

详细步骤见技能内的 `SKILL.md`（本仓库主文件）。
